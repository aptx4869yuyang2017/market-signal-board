## 页面定位

回答一个问题：**现在的交易是冷还是热？**

- 读者：本人，和周度 ERP 结论交叉验证。
- 主信号：**周度换手率**（最近 5 个交易日成交额合计 ÷ 同 5 日总市值合计）在 2024-09-24 以来样本中的分位。
- 换手率不判断好坏：热不等于风险、冷不等于机会，只描述拥挤度；与 ERP 页方向相反（**分位越高越热**）。
- 杠杆维度（融资余额 ÷ 流通市值、融资买入占比）已独立到「杠杆资金」页 [`leverage.md`](leverage.md)：本页看交易有多拥挤，杠杆页看仓位加到了多满。

## 数据契约

顶层结构：

```json
{
  "asof": "2026-11-11",
  "updated": "2026-11-15 21:21",
  "stats": {},
  "regime": {},
  "series": {},
  "log": [],
  "tiers": []

```

### `stats`（阈值与本周数据）

| 字段 | 类型 / 单位 | 含义 |
|---|---|---|
| `amount` | float，亿元 | 最新交易日成交额（备用） |
| `amount_chg_pct` | float，% | 本周日均成交额较上周的变化 |
| `turn` | float，% | 最新单日换手率（备用） |
| `turn_chg` | float，pp | 本周换手率较上周的差 |
| `cap_wan` | float，万亿 | 最近 5 个交易日均总市值 |
| `close` | float | 最新中证全指点位 |
| `week_amount` | float，亿元 | 最近 5 个交易日日均成交额 |
| `week_amount_pct` | float，% | `week_amount` 在 924 以来各周日均成交额中的分位 |
| `week_turn` | float，% | **本周换手率** = 5 日成交额合计 ÷ 5 日总市值合计（**主口径**） |

## 计算契约

### 换手率标准化

```text
日换手率%     = 当日成交额 ÷ 当日总市值 × 100
周度换手率%   = 最近 5 个交易日成交额合计 ÷ 同 5 个交易日总市值合计 × 100
```

- 分子取中证全指日频成交额；分母取沪深交易所月度「市价总值」。
- 月内用中证全指涨跌把上月锚点衔接到当日；每月最后交易日用官方值校准，并滚动锚点。
- 剔除成交额为 0 的节假日异常行；序列从 2014-01-01 起。
- 周度换手率用**合计相除**，不是「每日换手率求平均」：这样分子分母同步缩放，不受周内交易日数量影响。

为什么标准化：总市值随上市数量与股价上涨而扩张，成交额会被动抬升。直接看绝对值或其历史分位会系统性偏高。

### 分位

```text
pct = 924 以来各周周度换手率中「低于或等于当前值」的周数占比 × 100
```

- 越高越热，与 ERP 分位反向。
- 每个交易周取**当周最后一个交易日**为锚点，计算其最近 5 个交易日的合计换手率；台账与分位样本都用这组周值。
- 卡片主口径「本周」= 最近 5 个交易日，因此即使数据只到周中，也始终是完整的 5 日窗口。
- 冷热阈值 `cold` / `hot` 取 924 以来**周度**换手率的 20% / 80% 分位，与卡片、台账口径一致。

### 为什么从 924 起算

2024-09-24 政策转向后，两市成交额从 0.5–1 万亿平台抬到 1.5–3.5 万亿：

| 时期 | 成交额中位数 | 换手率中位数 |
|---|---|---|
| 924 前 | 约 0.62 万亿 | 约 0.98% |
| 924 后 | 约 1.88 万亿 | 约 1.88% |

两个平台量级不同，混算会让当前读数被旧平台带偏。因此卡片、阈值线、台账分位**统一只用 924 之后样本**；图表保留更早历史，并画竖虚线标出 924。

### 冷暖背景

- 仅标记 924 之后：**日换手率** ≤ `cold` 铺浅蓝 `rgba(59,110,165,.10)`，≥ `hot` 铺浅红 `rgba(192,57,43,.10)`。
- 阈值本身是周度分位，图上用日换手率穿越阈值来标记冷热时段。
- 连续段间隔 ≤6 个交易日先合并，再丢弃不足 5 个交易日的碎片。
- 是独立 series，可在图例单独开关。

### 成交额分位

`week_amount_pct` 用 924 以来各周的 5 日均成交额，但**没有剔除市值增长**，只作参考。判断冷热以周度换手率分位为准。

### 杠杆维度

已独立到「杠杆资金」页，计算与档位见 [`leverage.md`](leverage.md)。两页共用中证全指日频成交额，但坐标系、样本与判读方式互不影响。

## 文案与配色

### 命名

| 场景 | 用词 |
|---|---|
| 指标通用名 | **周度换手率**（weekly turnover） |
| 最新值卡片 / 周报 | **本周换手率** |
| 台账列头 | **周度换手率** |
| 禁用 | ~~周日均换手率~~（易读成「周日 均」） |

成交额侧保留「日均」概念，但写成「本周成交额（日均）」或「日均成交额」，不写「周日均成交额」。

### 文案

- 换手率两位小数，成交额整数（亿），分位一位小数，市值一位小数（万亿）。
- 主指标统一叫「本周换手率」或「周度换手率」，不要写「周日均换手率」，避免被读成「周日 均」。
- 「本周」= 最近 5 个交易日；「本周成交额（日均）」= 5 日成交额合计 ÷ 5，不要写成周成交额合计。
- 成交额分位卡说明固定带「按日均口径 · 未剔除市值增长」。
- 综合判断卡说明取 `regime.note`，不在前端拼接。
- 副标题固定包含：标准化口径、`分位样本自 2024-09-24`、数据截止、更新频率。
- 页脚必须保留三段解释：为什么标准化、为什么从 924 起算、卡片口径。

### 颜色语义

| 元素 | 规则 |
|---|---|
| 换手率分位 / 综合判断卡 | 底色 `档位色 + 14`，边框 `+55`，数值用档位色 |
| 成交额分位卡 | 同样按档位上色，但仅为参考 |
| 换手率较上周 | 上行暖色 `#c0392b`，下行冷色 `#3b6ea5`，持平灰 |
| 成交额较上周 | 同上，只表示冷热方向，不表示好坏 |
| 换手率折线 | `#e8833a`；成交额 `#7d9db5`；中证全指 `#a8a49c` |
| 冷 / 热底色 | 浅蓝 `rgba(59,110,165,.10)` / 浅红 `rgba(192,57,43,.10)` |
| 分位虚线 | `#cfcac1` 虚线，标注「924以来周度 80% / 20% 分位」 |

## 边界

### 口径一致性

页面卡片、台账、周报的「较上周」现在统一取**相邻两个周锚点**的周度指标差：

- `stats.turn_chg` = 本周换手率 − 上周换手率（pp）
- `stats.amount_chg_pct` = 本周日均成交额 / 上周日均成交额 − 1
- `summary_md` 直接复用这两个字段，不再从台账四舍五入后的值反推，避免 1bp 级误差。

### 其他边界

- 分母是总市值口径；换自由流通市值读数更高、波动更大，但冷热排序基本一致。
- 成交额受政策、IPO、交易制度影响，分位只描述历史相对位置。
- 924 样本会随时间变长，历史分位会缓慢漂移，不宜把 20% / 80% 当固定估值锚。
- 台账的历史分位用 924 以来全样本计算，不是「当时可知」的分位。
- 免费源无 SLA；抓取失败时 `monitor.py` 会降级到本地缓存，页面标注数据截止日。
- 页面为静态快照，运行脚本才更新。
- 杠杆资金（两融数据、档位、口径边界）见 [`leverage.md`](leverage.md)。
