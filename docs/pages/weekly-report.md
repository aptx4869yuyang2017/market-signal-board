# 契约 · 周报与飞书推送

| 字段 | 值 |
|---|---|
| 交付物 | 合并周报（ERP + 两市成交额） |
| 生成物 | `reports/<YYYY-Www>.md`、`reports/<YYYY-Www>.png` |
| 生成脚本 | `monitor.py`（`render_report` / `render_chart` / `notify`） |
| 推送渠道 | 飞书群自定义机器人（`config.yaml` → `push.feishu`） |
| 触发 | 每周六 10:00（DSH 计划任务）；也可手动运行 |
| 状态 | 使用中 |
| 最近更新 | 2026-11-16 · 建立契约文档 |

## 定位

周报是**一条能独立读懂的结论消息**，不是网页镜像。

- 读者：本人，在飞书里 10 秒内看完，决定本周是否调整定投/仓位。
- 只讲结论与关键数字，不搬图表、不铺台账。
- 固定用**主指数 + 10 年窗口**，与页面默认 5 年不同，这是有意为之：周报要稳定可比。
- 成交额段是交叉验证，不是第二个买卖信号。

## 输出与命名

| 产出 | 规则 |
|---|---|
| 周报 Markdown | `reports/{ISO 年}-W{ISO 周}.md`，例如 `reports/2026-W46.md` |
| 走势图 | 同名前缀 `.png`，主指数 ERP + 点位，2x 导出 |
| 推送正文 | 直接读取刚生成的 `.md` 全文 |
| 推送标题 | `股债性价比 {指数名} {MM-DD} · {ERP档位}`；成交额可用时追加 ` ｜ 成交{成交档位}` |

## 结构契约

正文顺序固定，段与段之间用 `***` 分隔（飞书会渲染成原生分割线）：

```markdown
**股债性价比**

{档位 emoji} ERP 10 年分位 {p10}% ≤{tier.max}% → {档位}
{双确认 emoji} 估值 10 年分位 {ey_p10}% {>|≤}{confirm}% → {双确认|单边}
{结论一句}

**ERP {erp}bp（周 {±n}bp）**
无风险利率 {y10}% ＋ 风险溢价 {erp_pct}% ＝ 股权收益率 {ey}%
分位 {p5}% / {p10}%（5 年 / 10 年）

***

**两市成交额**

{档位 emoji} 成交量 {档位} ｜ {档位说明}
**本周换手率 {week_turn}%  分位 {week_turn_pct}%**
（冷/热阈值 {cold}% / {hot}%） ｜ <font color='{orange|blue}'>{换手率 ±bp}</font>

本周成交额（日均） {x.xx 万亿 | n 亿}
分位 {week_amount_pct}% | 较上周 {±x.x}%

数据截至 {MM-DD}｜每周六 10:00 更新
```

### ERP 段

| 行 | 来源 | 规则 |
|---|---|---|
| 档位行 | `info.tier` + 10 年 ERP 分位 | 档位 emoji：极端便宜 🟩 / 偏便宜 🟢 / 中性 🟨 / 偏贵 🟧 / 贵 🟥 |
| 双确认行 | 收益率 10 年分位 vs `confirm_ey_pct` | 双确认 🟩，单边 🟧；符号按实际大小取 `>` 或 `≤` |
| 结论句 | `VERDICT_NOTE` | 固定口语化一句，不拼接数字 |
| ERP 行 | 最新 ERP 与周变化 | 周变化为 0 时写 `0bp`，不写 `+0bp` |
| 分解行 | `y10`、`erp_pct`、`ey` | 三者必须满足 `y10 + erp_pct = ey`（四舍五入误差 ±0.01） |
| 分位行 | 5 年 / 10 年 | 固定两个窗口，顺序不可换 |

### 成交额段

由 `turnover.summary_md(payload)` 生成，字段全部来自成交额 payload：

- 档位 emoji：冷清 🔵 / 偏冷 🟦 / 正常 🟨 / 偏热 🟧 / 过热 🟥。
- 换手率是**周度口径**：当周（最近 5 个交易日）成交额合计 ÷ 同 5 日总市值合计；不要写成「日均换手率」。
- 「较上周」与页面共用 `stats.turn_chg` / `stats.amount_chg_pct`，都是相邻两个周锚点的差，不再各算一套。
- 换手率变化换算成 bp，涨用 `<font color='orange'>`，跌用 `<font color='blue'>`，0 不加色。
- 成交额 ≥ 10000 亿显示「x.xx 万亿」，否则显示「n 亿」。
- 成交额段生成失败时，整段省略，ERP 段照常出报与推送。

### 页脚

固定一行：`数据截至 {指数数据日 MM-DD}｜每周六 10:00 更新`。数据截止指**指数/ERP** 的最后一个交易日，不是生成时间。

## 飞书渲染契约

`push_feishu` 把 Markdown 转成飞书交互卡片（`lark_md`），转换规则：

| Markdown | 飞书表现 |
|---|---|
| 正文首行 `# ` 标题 | 删除（标题走卡片 header） |
| `**加粗**` | 原生加粗 |
| `***` 单独一行 | 切成两个 `div`，中间插入原生 `hr` |
| 空行 | 丢弃，段间距由飞书控制 |
| 行首 🟩 🟢 🟨 🟧 🟥 🔵 🟦 | 整行包 `<font color='...'>`，绿/黄/橙/红/蓝 |
| `<sub>...</sub>` | 去掉标签，保留文字 |
| 表格、图片、多级标题 | 不支持，不要写进正文 |

卡片 header 固定橙色主题、宽屏模式。正文整段一条卡片发送，不拆分、不截断。

因此改文案时：

- 不要依赖空行做视觉分隔，用 `***` 或加粗行。
- 不要在正文里放链接、表格、代码块。
- emoji 只放在行首才有染色效果，放句中只当普通字符。
- 一条消息控制在飞书卡片大小限制内（当前正文约 500 字，远低于上限）。

## 生成与失败处理

1. `monitor.py` 生成 ERP 结果 → 写 `reports/<week>.md` 与 `.png`。
2. 成交额结果存在时，追加 `***` + 成交额摘要。
3. `notify` 读取 md 全文，拼标题，调用飞书 webhook。
4. 推送失败只打印 warning，不影响报告落盘与页面生成，退出码仍为 0。
5. `--no-push` 跳过推送；`--test-push` 只发一条测试消息，不跑主流程。

自检：

```bash
/opt/homebrew/anaconda3/bin/python3 monitor.py --test-push
```

## 边界

### 与页面口径一致

成交额段与页面卡片共用同一套周度指标与「较上周」：

- 本周换手率 = 最近 5 个交易日成交额合计 ÷ 同 5 日总市值合计。
- 本周成交额（日均）= 同 5 日成交额合计 ÷ 5。
- 分位样本 = 924 以来各周（以周末交易日为锚）的周度换手率。
- `summary_md` 直接读 `stats.turn_chg` / `stats.amount_chg_pct`，不再从四舍五入后的台账反推。

### 其他边界

- 周报只覆盖主指数，多指数对比看页面。
- ERP 固定 10 年分位，页面默认 5 年；两者结论可能不同，周报不解释差异。
- 推送是单向通知，不支持在飞书里点按钮回写。
- 免费数据源无 SLA，数据缺失时周报标注截止日，不做前向填充。
- 周报是个人监测记录，不构成投资建议。
