# 股债性价比 · 周度监控（ERP + 两市成交额）

每周六 10:00 自动抓数、算 ERP 与两市成交额，出合并周报、更新交互网页，并推送一条飞书通知。

**主口径：ERP = 中证全指收益率 − 10 年期国债收益率，单位 bp。**
（442bp 即 4.42%。为什么不看倍数，见文末。）

## 两市成交额页面

页面左侧可在「股债性价比 / 两市成交额」之间切换，成交额页独立观测交易冷热。

**为什么不直接看成交额**：总市值随上市数量与股价上涨而扩张，成交额也会被动抬升，
直接看绝对值（或它的历史分位）会系统性偏高。标准化口径：

```
日换手率 = 两市成交额 ÷ 沪深两市总市值 × 100%
```

再取换手率在 **2024-09-24 以来样本**内的历史分位判断冷热。分母用两市「市价总值」（总市值口径）；
若换成自由流通市值，读数更高、波动更大，但冷热排序基本一致。

**为什么分位从 924 起算**：2024-09-24 政策转向后，两市成交额从 0.5–1 万亿的平台系统性抬升到
1.5–3.5 万亿。924 前成交额中位数约 0.62 万亿、换手率约 0.98%；924 后中位数约 1.88 万亿、
换手率约 1.88%。两个平台量级不同，混在一起算分位会让当前读数被旧平台带偏，因此卡片、阈值线、
台账的分位**统一只用 924 之后的样本**；图表仍保留更早历史，并画一条竖虚线标出 924。

- **五张卡片（本周日均口径）**：本周日均换手率、日均换手率分位（924 以来）、综合判断、
  本周日均成交额、本周日均成交额百分位（924 以来，参考）。「本周日均」= 最近 5 个交易日均值，
  对应分位在 924 以来滚动 5 日均序列中计算，降低单日噪声。
- **趋势图**：默认展示近 3 年，左轴换手率（%）、右轴成交额（亿元，默认隐藏，可在图例打开），
  另加一条中证全指曲线辅助判断；两条 924 以来 20% / 80% 分位虚线，竖虚线标 924。
- **冷暖背景带**：仅 924 之后，换手率低于 20% 分位铺浅蓝（冷）、高于 80% 分位铺浅红（热），
  在图例中可独立开关。
- **时间按钮**：1 / 3 / 5 / 10 年 / 全部，只切换图表区间；分位固定按 924 以来计算
- **近 12 周台账**：周日均成交额、周日均换手率、924 以来分位、信号胶囊（周日均 = 当周 5 个交易日均值，排除特殊日期影响）
- 颜色语义：分位卡按档位染色（蓝 = 冷、黄 = 正常、橙红 = 热）；
  成交额与换手率的「较上周」上涨用暖色、下跌用冷色，只表示冷热方向，不表示好坏

| 换手率分位 | 档位 | 含义 |
|---|---|---|
| ≤20% | 冷清 | 成交低迷，情绪处在冰点 |
| 20–40% | 偏冷 | 交投偏淡，观望情绪较重 |
| 40–60% | 正常 | 活跃度中性，没有明显拥挤 |
| 60–80% | 偏热 | 交投升温，注意交易拥挤 |
| >80% | 过热 | 情绪过热，留意回撤风险 |

数据：成交额与点位取中证全指（000985）日频；两市总市值取沪深交易所月度市价总值，
月内按指数涨跌衔接、月末用官方值校准。单独运行：`python turnover.py`（可加 `--no-fetch`）。

周报 `reports/<YYYY-Www>.md` 与推送正文里也会自动带一段成交额摘要：本周日均成交额（万亿）、
日均换手率、924 以来分位、冷热档位与较上周变化。

## 信号规则

主判定看 **ERP 的 10 年便宜度分位**（越低越便宜）：

| 分位 | 档位 | 颜色 | 动作 |
|---|---|---|---|
| ≤20% | 极端便宜 | 深绿 | 加仓区 |
| 20–40% | 偏便宜 | 浅绿 | 定投/加仓 |
| 40–60% | 中性 | 黄 | 维持 |
| 60–80% | 偏贵 | 橙 | 减少买入 |
| >80% | 贵 | 红 | 防守 |

网页上的卡片会跟着所选时间窗口实时重算；周报固定用 10 年窗口。

辅助规则：

- **绝对参考线**：ERP ≥ 400bp 视为较好的加仓区间，< 200bp 视为债券更有吸引力（只作参考）
- **双确认**：中证全指收益率（=1/PE）的分位 ≤40% 才算「真便宜」；否则是「单边便宜」，只有债券端在动

当前是典型例子：ERP 442bp、10 年分位 14.9%（档位「极度便宜」），但估值分位 51.3%（中位数），
所以结论是**单边便宜**，不是全面低估。

## 推送配置（飞书）

推送只走飞书群机器人。Webhook 属于敏感凭据，存放在项目根目录的 `.env`（已被 `.gitignore` 排除，不会进 git）：

```bash
FEISHU_WEBHOOK=https://open.feishu.cn/open-apis/bot/v2/hook/xxxx
```

获取方式：飞书群 → 设置 → 群机器人 → 添加自定义机器人 → 复制 Webhook（免费额度 100 次/分钟）。`config.yaml` 里通过占位符引用：

```yaml
push:
  feishu:
    enabled: true
    webhook: "${FEISHU_WEBHOOK}"
```

自检：

```bash
/opt/homebrew/anaconda3/bin/python3 monitor.py --test-push
```

会在飞书群收到一条测试消息。之后每周六的合并周报正文（ERP + 两市成交额，Markdown）会原样推送过去。

## 为什么不用倍数

倍数 = 股权收益率 ÷ 国债收益率，问题在分母：

- 2019 年底以来倍数从 1.96 涨到 3.75（×1.91），其中**利率贡献 103%、盈利收益率 −3%**
- 同样的 6.02% 收益率，2014 年（国债 4.64%）对应倍数 1.30，今天（1.60%）对应 3.75
- 现在 10bp 的利率变动会让倍数跳 6.2%（2014 年只有 2.4%）
- 倍数分位混入了高利率时代，天然显得「现在极度便宜」

ERP 能避开这些：可加、可归因（ΔERP = Δ收益率 − Δ利率）、不会发散。
用未来 12 个月收益的秩相关检验：全样本 IC 差值 0.50 vs 倍数 0.39。

## 已知差异

中证官网 `peg` 的 PE 与银行口径不同，倍数绝对值差约 0.5（我们 3.75 vs 图上 3.24），
但分位几乎一致（6.3% / 3.1% vs 6.50% / 3.23%）。ERP 不受这个影响，因为用的是收益率差值。
